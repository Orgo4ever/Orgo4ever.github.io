JobScout NL

A personal job-search decision-support workflow that collects vacancies, checks constraints, links requirements to candidate evidence and preserves human control over application decisions.

PythonAPIsGitHub ActionspytestGoogle Sheets

The problem

Job boards mix genuinely relevant opportunities with unsuitable locations, seniority levels, specialist requirements, temporary roles and posts that are not eligible for Netherlands-based applicants. Simple keyword scores can rank these unsuitable vacancies highly, creating avoidable manual work.

JobScout NL was designed to separate professional fit from eligibility and logistical constraints, and to make screening decisions inspectable rather than opaque.

Workflow design

  1. Collect: retrieve vacancies from configured employer career-board sources.
  2. Normalize: structure records and keep track of previously seen vacancy links.
  3. Evaluate: screen hiring geography, relevant qualifications, role seniority and documented experience.
  4. Review: produce an evidence-backed shortlist with unresolved requirements visible.
  5. Preserve decisions: maintain manually reviewed applications and feedback independently of automated outputs.
  6. Automate carefully: schedule collection and testing without submitting job applications on the user's behalf.

Reliability and human oversight

  • Automated tests cover screening and other workflow components; GitHub Actions supports recurring checks and data collection.
  • Google Sheets synchronization separates machine-generated results from human-maintained application decisions.
  • Conservative handling of unclear geography and mandatory requirements helps avoid treating an unverified posting as eligible.
  • Review notes and documented caveats make heuristic scores explainable, but do not turn them into predictions of interview success.
This is a personal workflow, not a production recruitment platform. A vacancy score is a screening heuristic, not an assessment of legal work eligibility or hiring probability. Employer requirements and the original posting still require human verification.

Why this project matters

The main technical challenge was not creating one visualization. It was building a repeatable system with changing external data, quality checks, feedback handling, safe automation and explicit limitations. This provides relevant evidence for operations analysis, data quality, technical operations and junior analytics-engineering roles.

Access

The working GitHub repository is private because it includes personal configuration and application-tracking context. This public case study is a high-level technical summary; it does not expose source code, personal job records, credentials or private configurations. No measured improvement in hiring outcomes is claimed.
